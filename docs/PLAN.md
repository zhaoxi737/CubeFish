# QDOQMC 总计划 v0.1

> AI 驱动的《我的世界》启动器。核心体验：一个大启动按钮 + 一个 AI 聊天框，其余全部收起。
> 原则：**先免费做口碑，但从第一天就为收费留好缝**。

状态：计划阶段（未开工）。本文件随需求变化持续更新。

---

## 1. 定位

不是"又一个启动器"，而是：

- **极简**：默认路径最短，一键启动；复杂功能收进命令面板 / 抽屉。
- **AI 驱动下载**：用户说"装个 XX 光影"，AI 自己完成 搜索 → 解依赖 → 冲突预检 → 下载校验 → 落盘到对应实例。
- **能自己长大**：一切皆插件（复用 Harness / Cordis 内核），AI 可以生成新插件给启动器加功能。
- **崩了能治**：结构化日志 + 崩溃归因 + 一键修复建议。

明确不做的事：不内置游戏文件、不绕过正版验证、不卖用户数据、不贴广告。

### 2.2 非功能

- Windows 10/11 优先（暂只做 Windows）。
- 冷启动 < 3 秒；无网络时除下载功能外全部可用。
- 崩溃率 < 2%；7 日留存目标 > 35%。
- 磁盘：装 10 个同版本实例不得重复占用资源。

## 3. 架构

```
┌─────────────────────────────────────────────────────────────┐
│ Renderer（Electron）                                          │
│   极简主界面：实例条 + 大启动键 + AI 聊天                     │
│   其余面板 = 可插拔 UI 插件（版本/模组/日志/设置/市场）        │
├─────────────────────────────────────────────────────────────┤
│ Main（Node / Cordis 容器）                                    │
│   launcher-core   实例 / 版本 / 文件系统 / 进程               │
│   launch-engine   classpath / natives / 参数 / 子进程          │
│   java-runtime    探测 / 下载 / 版本匹配                      │
│   downloader      并发队列 / 续传 / 校验 / 镜像               │
│   content         Modrinth/CurseForge 适配器 / 依赖求解       │
│   conflict        静态分析 + 日志归因 + 已知冲突库            │
│   agent-bridge    agent 运行时 + 工具注册 + 审计              │
│   plugin-host     插件加载 / 权限 / 市场                      │
│   cloud           更新 / 统计 / 授权 / 账号（默认空实现）      │
├─────────────────────────────────────────────────────────────┤
│ 数据：SQLite（实例/内容/任务/事件索引）+ 实例内 manifest JSON  │
│ 文件：全局缓存区（共享）+ 实例目录（隔离）                     │
└─────────────────────────────────────────────────────────────┘
```

选型（待最终确认，默认按此推进）：

| 层 | 选择 | 说明 |
|---|---|---|
| 外壳 | Electron + React + TypeScript | 插件内核是 TS/Node，前端面板天然可插件化 |
| 插件内核 | `@deepseek-ai/cordis`（MIT, 4.0.5） | 复刻 Harness「一切皆插件」 |
| AI 运行时 | `dsh-base` + `dsh-sdk-app`（stdio JSON-RPC） | 备选：自研 agent，工具协议对齐 MCP |
| 数据 | SQLite（better-sqlite3） | 单文件、可迁移 |
| 内容源 | Modrinth API v2 优先，CurseForge 可选 | Modrinth 免 key |
| 游戏源 | Mojang piston-meta 官方 manifest | 合规 |

风险：dsh 为 `0.2.1-rc`，API 会漂 → **锁版本 + 适配层**，启动器不直接依赖其内部 API。

## 4. 商业化预留（本版核心）

现在一分钱不收，但以下 8 个"缝"必须在 P0/P1 埋好。埋缝成本约占总工作量 10%，事后补要重构 40%。

| # | 缝 | 现在怎么做（免费态） | 以后怎么变成钱 | 埋设阶段 |
|---|---|---|---|---|
| 1 | **CloudPort 抽象** | 所有联网能力走 `cloud` 服务接口，默认 `local/null` 实现；无后端也全功能可用 | 换成 Cloudflare / 自建实现，核心代码零改动 | P0 |
| 2 | **统一身份** | 只有匿名 `install_id`，但结构是"主体 ID + 令牌" | 升级为正式账号（设备绑定→账号绑定），云存档/授权/订单全挂这个 ID | P0 |
| 3 | **授权门控 Entitlement** | 每个功能插件声明 `requires: basic/pro`，默认全部放行 | 接授权服务下发签名 License（可离线校验、可过期、可吊销） | P0 |
| 4 | **AI 双通道** | 只做通道 A：用户自带 API Key（本地加密存储，免费直连） | 通道 B：托管额度（走你的代理，计量/限额/计费）—— **用户自填 key 意味着 AI 不赚钱，B 才是收入** | P0 留接口，P4 实现 A |
| 5 | **存储抽象（云存档地基）** | 存档/配置/截图走 `storage` 接口，本地 FS 实现；目录按"可同步/不可同步"分层 | 加一个云后端 + 冲突合并策略 = 云存档订阅 | P1 布局，P3 实现 |
| 6 | **Feed 机制（市场地基）** | 插件市场/整合包市场共用「静态 JSON 清单 + 签名校验 + 增量下载」 | 同一套机制做付费分发与分成，不重写 | P4（先免费分发） |
| 7 | **事件埋点** | 只写本地 `events.jsonl`，opt-in 才上报 | 转化漏斗（安装→启动→留存→付费）直接复用 | P0 |
| 8 | **付费功能插件化** | 付费能力全部做成插件，不进核心 | 不付费用户零影响；退款/吊销只改服务端权限，不发版 | P4 |

### 收费前必须具备的三个"地基"（非功能，但决定能不能收钱）

1. **强制更新通道**——收费后必须有办法强制升级/停机维护（`minSupported` 字段，见第 5 节）。
2. **远程功能开关**——某个付费功能出问题能一键关掉，而不是紧急发版。
3. **授权离线校验**——断网也要能用（签名 License + 宽限期），否则用户骂街。

### 变现路线图（与用户量挂钩）

| 阶段 | 用户量 | 动作 | 收入 |
|---|---|---|---|
| 0 | 0–1000 | 全免费，只做「能玩、不崩、装得爽」；早鸟 5 元仅作身份标识与种子群，明确写"未来增值功能可能另计" | ≈0 |
| 1 | 1000–1 万 | 云存档订阅（成本最低、毛利最高，3–6 元/月）；启动器 Pro 买断可选 | 首笔现金流 |
| 2 | 1 万+ | AI 额度托管（10–20 元/月，需生成式 AI 合规备案）；整合包市场分成 | 主要收入 |
| 3 | — | 联机/一键开服（最愿意付费的场景，可先接第三方分成）；B 端定制版 | 高客单 |

核心判断：**免费竞品（PCL2/HMCL/BakaXL）已把"启动器基础功能"价格锚定为 0**，所以只能卖"省事"和"服务"，不能卖"能启动游戏"。

## 5. 更新与统计（运维）

### 5.1 自动更新

```
启动 → GET cdn/latest.json → 版本对比 → 后台静默下载 → 角标提示重启 → 安装器替换
```

```json
{ "version": "1.3.2", "url": ".../QDOQMC-1.3.2.exe", "sha256": "...",
  "notes": "...", "minSupported": "1.0.0", "rollout": 100 }
```

- 静态文件 + CDN（OSS/COS/R2），不自建常驻更新服务。
- `electron-updater` + NSIS 差量更新；sha256 + HTTPS 强校验；失败静默跳过，不阻塞启动。
- `rollout` 灰度，`minSupported` 强制更新；保留上一版本以便回滚。
- 多源回退（主 CDN → GitHub Releases → 备用域名）。
- 代码签名（约 ¥1500–3000/年），有收入后再买。

### 5.2 统计

- 客户端：首次启动生成 `install_id`（随机 UUID），每日首次启动/启动游戏时上报一次。
- 上报：`install_id / 版本 / 系统 / 事件 / MC 版本 / 加载器 / 是否崩溃`。**不上报**账号、游戏 ID、路径、聊天、API Key。
- 服务端：Cloudflare Worker + D1（前几千用户免费），或 Supabase。
- 看板指标：今日活跃设备、累计设备、版本分布、启动成功率、崩溃率、7 日留存、新增。
- 隐私：首启说明 + 设置可关 + 隐私政策；遵守 PIPL。API Key 只存本地（`safeStorage`）。

## 6. 数据模型（初稿）

- `instances`：id, name, mc_version, loader, loader_version, java_path, memory_mb, dir, created_at
- `content`：id, instance_id, source(modrinth), project_id, version_id, kind(mod/pack/shader), file, hash, enabled
- `events`：id, ts, install_id, type, payload（本地 jsonl + 可选上报）
- `download_tasks`：url, dest, hash, size, status, attempts
- `entitlements`（现为空表）：subject_id, feature, expires_at, license_sig
- `settings`：键值

## 7. 里程碑

| 阶段 | 内容 | 验收标准 | 估算 |
|---|---|---|---|
| **P0 骨架** | Electron + Cordis 容器、极简 UI、结构化日志、设置、cloud/identity/entitlement/storage 抽象的默认实现、更新检查 | 应用能跑、能记录事件、能检查更新（无后端也不崩） | 3–5 天 |
| **P1 能玩** | 原版下载、Java、实例隔离、内存、启动、离线登录 | 双击启动任意原版版本进游戏；崩溃有日志 | 2–3 周 |
| **P2 能装** | Modrinth 搜索/依赖求解/一键装、Fabric+NeoForge、`.mrpack`、统计上报 | 说"装个 XX"能装进正确实例并启动 | 2–3 周 |
| **P3 能治** | 静态冲突分析、崩溃归因、AI 读日志给修复方案 | 注入已知坏 mod 能自动定位并建议修复 | 2 周 |
| **P4 能长** | 能力工具化给 AI、插件内核/权限/市场、AI 写插件 | 装一个社区插件能新增面板与 AI 工具 | 3–4 周 |
| **P5 交付** | 自动更新全链路、安装包、性能、兼容矩阵 | 老版本用户能平滑升级 | 1–2 周 |

P1 结束（约 3 周）即拥有可玩的启动器；之后每阶段都是可用增量。

## 8. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| Forge processors 安装复杂 | 装不上 Forge | 先 Fabric/NeoForge，Forge 单独攻坚；失败给清晰报错 |
| 微软登录需 Azure 应用 | 正版登录卡住 | 先离线；需要时注册免费 Azure 应用 |
| dsh rc 版本 API 漂移 | 架构返工 | 锁版本 + 适配层 + 可回退自研 agent |
| 插件 = 任意代码执行 | 安全事故 | 权限分级 + 白名单 + 审计 + 用户确认 |
| 用户自填 Key 无法变现 | 收入依赖云存档/联机 | 见第 4 节路线图 |
| 合规（ICP/支付/生成式 AI 备案） | 收费被卡 | 收费前一次性列清单办理 |
